🛠️ 2. Preparando o Ambiente para o Primeiro Hello World

MPLAB X IDE

Abaixo está o passo a passo resumido para configurar um novo projeto no MPLAB X IDE e criar o arquivo C inicial:

1
Criar Novo Projeto

Abra o MPLAB X IDE, vá no menu superior em File > New Project... (ou utilize o atalho Ctrl + Shift + N). Selecione a categoria Microchip Embedded e o tipo Standalone Project. Clique em Next.

2
Selecionar o Dispositivo (PIC16F877A)

No campo Device, digite PIC16F877A. A família será definida automaticamente como Mid-Range 8-bit MCUs (PIC10/12/16). Clique em Next.

3
Selecionar a Ferramenta de Gravação

Na etapa Select Tool, selecione Simulator ou deixe em branco / None. Como utilizaremos o software externo AN1310 para transferir o arquivo compilado via USB, a IDE não precisa gerenciar gravadores de hardware proprietários diretamente.

4
Selecionar o Compilador XC8

Selecione o compilador XC8 instalado em seu sistema. Em seguida, dê um nome ao projeto (por exemplo, aula01_led) e defina a pasta de destino no computador.

5
Criar o Arquivo Fonte C Vazio

Com o projeto criado, expanda a árvore do projeto na aba lateral Projects, clique com o botão direito na pasta Source Files > New > C Source File..., nomeie como main.c e finalize. Um arquivo limpo será aberto no editor.

🐢 3. Construindo o Código – LED (Pista Lenta)

Fundamentos & Fuses

Por padrão, o arquivo C abre com a biblioteca do microcontrolador já incluída (indispensável para podermos interagir com ele) e a estrutura básica da função principal com return;:

Inclusão e estrutura inicial
#include <xc.h>  // Biblioteca de comunicação com o microcontrolador; sem ela não é possível interagir com os registradores.

void main(void) {
    return;
}

Fora isso, algumas configurações fundamentais de hardware (chamadas de fuses ou bits de configuração) precisam ser definidas antes da execução do programa. Clique em qualquer um dos blocos abaixo para expandir a explicação técnica detalhada:

#pragma config FOSC = HS Clock & MIPS (8 MHz)
Detalhes ▼

Definição: Define a fonte física de clock que comanda o ritmo de funcionamento do microcontrolador.

  • HS (High Speed): Para cristais de alta velocidade (acima de 4 MHz, como o cristal de 8 MHz presente na placa ACEPIC).
  • XT: Para cristais de média ou baixa velocidade (até 4 MHz).
  • RC: Para osciladores baseados em circuitos resistor-capacitor.

Regra dos Ciclos para a Família PIC16:

A arquitetura da linha PIC16 opera com uma proporção fixa de 4 ciclos de clock do oscilador para executar 1 ciclo de instrução.

Dessa forma, como o oscilador da placa ACEPIC trabalha a 8 MHz (8.000.000 Hz), dividindo esse valor pelo número de ciclos por instrução, temos:

8.000.000 ÷ 4 = 2.000.000 de instruções por segundo (2 MIPS)

Cálculo do tempo de cada instrução:

  • 8 MHz ÷ 4 = 2 MIPS → 1 / (2 MIPS) = cada instrução leva 0,5 µs para rodar.
  • 16 MHz ÷ 4 = 4 MIPS → 1 / (4 MIPS) = cada instrução levaria 0,25 µs para rodar.

Isso é fundamental de ser compreendido, pois esse valor afeta diretamente o comando de delay (tempo de espera) que utilizaremos no código.

#pragma config WDTE = OFF Watchdog Timer
Detalhes ▼

O que é (Watchdog Timer): Um "cão de guarda" com temporizador analógico independente que força um reset físico no chip caso o software trave.

Funcionamento: Estoura, em média, a cada 18 ms. Considerando um sistema a 2 MIPS (0,5 µs por instrução), ele suporta aproximadamente 36.000 instruções antes de disparar o reset obrigatório.

Uso prático: É excelente para confiabilidade em sistemas industriais, mas exige o uso da instrução CLRWDT() em pontos estratégicos (trechos maiores que 10 ms) para limpar o contador. Em aulas introdutórias e projetos didáticos, deve ficar em OFF para evitar reinicializações indesejadas durante os atrasos normais do programa.

#pragma config PWRTE = ON Power-up Timer (72ms)
Detalhes ▼

O que é (Power-up Timer): Um atraso fixo de segurança de cerca de 72 ms aplicado logo após a alimentação ser ligada, mantendo o chip "congelado" até que a tensão de 5V da fonte estabilize completamente.

Vantagens vs. Desvantagens: Deixar ligado (ON) evita leituras falsas e comportamentos erráticos na inicialização. Desligar (OFF) só faz sentido em sistemas críticos de partida instantânea onde cada milissegundo inicial é vital. Na ACEPIC, recomendamos manter ON.

#pragma config BOREN = ON Brown-out Reset
Detalhes ▼

O que é (Brown-out Reset): Sistema de segurança que reinicia o microcontrolador caso a tensão de alimentação caia abaixo de um limite seguro (~4,0V).

Atenção: Em projetos alimentados por pilhas ou baterias que descarregam lentamente, mantê-lo ativo pode fazer o sistema entrar em um loop infinito de reinicializações à medida que a carga da bateria diminui. Para alimentação via fonte na bancada, mantê-lo ativo (ON) previne travamentos por flutuações de tensão.

#pragma config LVP = OFF Liberação do Pino RB3
Detalhes ▼

O que é (Low-Voltage Programming): Habilita a gravação do chip usando baixa tensão (5V) em vez da alta tensão tradicional de 12V no pino MCLR.

Impacto direto no hardware: Com LVP = ON, o pino RB3 fica reservado exclusivamente como sinalizador de programação e não pode ser utilizado no circuito. Com LVP = OFF, o pino RB3 fica totalmente livre para ser usado como entrada ou saída digital comum (botões, LEDs, etc.).

#pragma config CPD = OFF, WRT = OFF, CP = OFF Proteção de Memória
Detalhes ▼
  • CPD = OFF: Desativa a proteção de leitura da memória EEPROM interna do microcontrolador.
  • WRT = OFF: Desativa a proteção contra escrita na memória Flash de programa, permitindo que o bootloader AN1310 grave novos firmwares no chip sem bloqueio.
  • CP = OFF: Desativa a proteção contra cópia e leitura do código gravado na memória Flash, permitindo a verificação e depuração do firmware.
#define _XTAL_FREQ 8000000 Base de Tempo do __delay_ms()
Detalhes ▼

O que é: Diretiva obrigatória do compilador XC8 para que as funções nativas de atraso de tempo, como __delay_ms(), possam calcular com precisão matemática o número exato de ciclos em vazio necessários para atingir o tempo desejado.

Exemplo prático — Atraso de 2 ms (2.000 µs):
• Com cristal de 8 MHz (0,5 µs por instrução) → o compilador gera um loop interno de exatas 4.000 instruções.
• Com cristal de 16 MHz (0,25 µs por instrução) → seriam necessárias 8.000 instruções para atingir o mesmo tempo real.

Reunindo as inclusões de bibliotecas, as configurações dos fusíveis de hardware (fuses) e a definição da frequência de operação do cristal, a estrutura inicial do código antes da configuração dos pinos fica assim:

main.c — Estrutura Inicial (Fuses e Definições) 
#include <xc.h>
#include <stdio.h>

// Configurações dos Fuses de Hardware
#pragma config FOSC  = HS   // Cristal de alta velocidade (8 MHz na placa ACEPIC)
#pragma config WDTE  = OFF  // Watchdog Timer desativado (evita reinicializações durante o delay)
#pragma config PWRTE = ON   // Power-up Timer ativado (estabiliza os 5V na inicialização)
#pragma config BOREN = ON   // Brown-out Reset ativado (protege contra queda de tensão)
#pragma config LVP   = OFF  // Low-Voltage Programming desligado (libera o pino RB3)
#pragma config CPD   = OFF  // Proteção de dados da EEPROM desligada
#pragma config WRT   = OFF  // Proteção de escrita em Flash desligada (livre p/ o bootloader)
#pragma config CP    = OFF  // Proteção contra leitura de código desligada

// Frequência do oscilador físico para cálculo dos atrasos de tempo
#define _XTAL_FREQ 8000000  // 8 MHz

void main(void) {
    return;
}

Controlando os Pinos: Os Registradores TRIS e PORT

Uma vez definidas as configurações acima, o código para interagir com os LEDs da placa é direto. O controle dos pinos baseia-se em dois passos: definir a função (entrada ou saída) e depois definir o estado (nível lógico 0 ou 1).

1. Definindo Direção com o TRIS (Entrada ou Saída):

Primeiro é necessário definir se os pinos da porta serão para entrada ou para saída. Existem duas formas de fazer isso: individualmente ou todos de uma vez: 

TRISD = 0b00000000;        // Todos os 8 pinos da Porta D são definidos como SAÍDA (0 = saída, 1 = entrada)
TRISDbits.TRISD0 = 0;     // Apenas o pino 0 (RD0, correspondente ao LED mais à direita) ficará como saída

Alterar os valores dos bits entre 0 e 1 altera a sua definição (0 = Output / Saída; 1 = Input / Entrada).

2. Definindo o Nível Lógico com o PORT:

Uma vez com a função dos pinos definida, é preciso dizer qual o estado elétrico atual deles. Para isso usamos o registrador PORT, seguindo o mesmo padrão: 

PORTD = 0b00000001;        // Todos os LEDs desligados, exceto o primeiro (RD0 em nível alto, acendendo o LED)
PORTDbits.RD0 = 1;        // Mesma coisa, mas definindo individualmente apenas o primeiro pino (liga o primeiro LED)

Padrão de nomenclatura no XC8: Vale salientar que o padrão de acesso bit a bit segue a estrutura TRIS_letra_num e PORT_letra_num. Por exemplo, para manipular pinos da Porta E poderíamos usar TRISEbits.TRISE0 = 0; para definir a direção e PORTEbits.RE0 = 1; para setar o nível lógico do pino.

Formatos de Escrita no C: Binário ou Hexadecimal?

Ao atribuir valores ao registrador PORTD no compilador XC8, você pode escolher a representação numérica de sua preferência:

  • Binário (prefixo 0b): Ex: PORTD = 0b00000001; — É a forma mais intuitiva e didática para iniciantes, pois cada dígito (0 ou 1) reflete diretamente o estado físico do respectivo pino no barramento (RD7 até RD0).
  • Hexadecimal (prefixo 0x): Ex: PORTD = 0x01; — Muito utilizada profissionalmente por ser compacta. Cada dígito hexadecimal agrupa exatamente 4 bits (um nibble). Por exemplo, acender os 8 LEDs é simplesmente PORTD = 0xFF; (onde F = 1111).

💻 4. Código Completo & Compilação

Firmware XC8

Juntando todas as definições vistas na Pista Lenta, a estrutura final do programa para piscar o primeiro LED da placa ACEPIC PRO fica assim:

main.c — Código Completo do Pisca-LED 
#include <xc.h>
#include <stdio.h>

// Configurações dos Fuses de Hardware
#pragma config FOSC  = HS   // Cristal de alta velocidade (8 MHz na placa ACEPIC)
#pragma config WDTE  = OFF  // Watchdog Timer desativado (evita reinicializações durante o delay)
#pragma config PWRTE = ON   // Power-up Timer ativado (estabiliza os 5V na inicialização)
#pragma config BOREN = ON   // Brown-out Reset ativado (protege contra queda de tensão)
#pragma config LVP   = OFF  // Low-Voltage Programming desligado (libera o pino RB3)
#pragma config CPD   = OFF  // Proteção de dados da EEPROM desligada
#pragma config WRT   = OFF  // Proteção de escrita em Flash desligada (livre p/ o bootloader)
#pragma config CP    = OFF  // Proteção contra leitura de código desligada

// Frequência do oscilador físico para cálculo dos atrasos de tempo
#define _XTAL_FREQ 8000000  // 8 MHz

void main(void) {
    TRISD = 0b00000000;     // Todos os pinos da Porta D são definidos como saída
    PORTD = 0b00000000;     // Inicializa todos os LEDs apagados

    while(1) {
        PORTD = 0b00000001; // Liga apenas o LED 0 (pino RD0)
        __delay_ms(200);    // Atraso de 200 ms: essencial para que seja possível ver os
                            // LEDs alternando a olho nu, já que as oscilações do
                            // microcontrolador ocorrem na ordem de microssegundos.
        PORTD = 0b00000000; // Desliga o LED 0 (pino RD0)
        __delay_ms(200);    // Aguarda 200 ms desligado
    }
}

🚀 5. Processo de Gravação (Bootloader AN1310)

Deploy

Para ver o código funcionando fisicamente, é necessário gravá-lo na placa. Para isso usamos o programa AN1310, que é o nosso bootloader. Ele vem nos programas disponíveis dentro do arquivo .zip que baixamos anteriormente do site da ACEPIC.

Uma vez com o AN1310 instalado e aberto, confira se as seguintes configurações estão ajustadas no menu Program > Settings... (ou pressionando a tecla F12):

Menu Program > Settings... (F12)
Ajustes obrigatórios em Settings (19200 bps)

Pontos de Atenção na Janela Settings:

  • COM Port: Selecione a porta correspondente à conexão USB da placa (ex: USB-SERIAL CH340 (COM3)).
  • Bootload Baud Rate & Application Baud Rate: Devem estar ajustadas em 19200 bps.
  • Write Options: Deixe marcada a opção FLASH Program Memory e desmarcadas as caixas Config Bits e EEPROM.

Passo a Passo da Conexão e Gravação

1
Pressionar o Botão Break

No AN1310, clique no botão Break (ou pressione a tecla F3).

2
Apertar o Botão de Reset Físico da Placa

Aperte o botão físico de Reset da placa, localizado à direita do painel de botões na parte inferior da placa ACEPIC. Isso fará a placa entrar temporariamente em modo de bootloader, aguardando conexão.

3
Apertar o Botão Vermelho no AN1310

Logo após soltar o botão de reset na placa, clique no botão vermelho no software (ou pressione a tecla F4).

Logo abaixo, no rodapé da janela, será possível ver se a placa se conectou ao bootloader com sucesso (mostrando a identificação do PIC16F877A), e uma tela como esta deverá aparecer:

Placa conectada com sucesso no Bootloader AN1310 🔍 Clique para ampliar
4
Selecionar o Arquivo HEX Compilado

Depois disso, basta ir no menu File > Open e procurar onde o seu arquivo .hex foi compilado (caminho exibido pelo MPLAB X na mensagem de sucesso da compilação).

5
Gravar o Código (Botão Write)

Uma vez com o arquivo .hex selecionado, basta clicar no botão Write (ícone com a seta vermelha para baixo apontando para o chip, ou pressione F6):

Botão Write destacado na barra do AN1310 🔍 Clique para ampliar
6
Reiniciar e Executar!

Com isso feito, basta apertar o botão físico de Reset na placa (ou o botão Run no AN1310), e o código gravado já deverá rodar perfeitamente, fazendo o LED piscar!

⚡ 6. Pista Rápida (Passo a Passo Mecânico)

Checklist de Bancada

Para quem já possui experiência com microcontroladores e deseja apenas o roteiro prático e mecânico de gravação na bancada, siga a ordem direta abaixo:

  1. Chaves de Hardware: Ajuste as chaves nos DIP switches DP1 (chaves 5 e 7 em ON) e DP2 (chaves 5, 6, 7 e 8 em OFF).
  2. Conexões: Conecte a fonte de alimentação e o cabo de comunicação USB na placa.
  3. Projeto no MPLAB X: Crie um projeto Standalone para o dispositivo PIC16F877A com compilador XC8 e crie o arquivo main.c.
  4. Firmware: Cole o código em C com os fuses (FOSC=HS, WDTE=OFF, PWRTE=ON, BOREN=ON, LVP=OFF), _XTAL_FREQ 8000000, TRISD = 0b00000000; e o loop de acionamento do LED com delay.
  5. Compilação: Clique em Clean and Build Main Project e verifique o caminho do arquivo .hex gerado.
  6. Configuração do Gravador: Abra o software AN1310 e certifique-se de que em Settings a porta COM está selecionada a 19200 bps com FLASH Program Memory marcada.
  7. Sincronização: Clique no botão Break (ou F3) → pressione o botão físico de Reset na placa ACEPIC → clique no botão vermelho (ou F4).
  8. Gravação: Vá em File > Open, selecione o arquivo .hex e clique no botão Write (ou F6).
  9. Execução: Pressione novamente o botão físico de Reset na placa. O LED começará a piscar imediatamente.

✅ Solução Proposta — Walking LED (main.c)

Kit ACEPIC PRO V8.0

Abaixo está a implementação sugerida para acionar individual e sequencialmente os pinos RD0 a RD7 (L1 a L8) com atrasos de 200 ms:

main.c — Resposta Final do Desafio 
#include <xc.h>

// Configurações de Hardware (Fuses)
#pragma config FOSC = HS        // Cristal de Alta Velocidade (8 MHz)
#pragma config WDTE = OFF       // Watchdog Timer desligado
#pragma config PWRTE = ON       // Power-up Timer ligado
#pragma config BOREN = ON       // Brown-out Reset ligado
#pragma config LVP = OFF        // Low-Voltage Programming desligado (libera RB3)

#define _XTAL_FREQ 8000000      // 8 MHz de clock (2 MIPS)

void main(void) {
    // 1. Configura toda a Porta D (RD7 até RD0) como Saída (0) de uma vez só
    TRISD = 0b00000000; 
    
    // Garante que a porta começa limpa
    PORTD = 0b00000000;

    while(1) {
        PORTD = 0b00000001; // Liga apenas o L1 (RD0)
        __delay_ms(200);
        PORTD = 0b00000010; // Liga apenas o L2 (RD1)
        __delay_ms(200);
        PORTD = 0b00000100; // Liga apenas o L3 (RD2)
        __delay_ms(200);
        PORTD = 0b00001000; // Liga apenas o L4 (RD3)
        __delay_ms(200);
        PORTD = 0b00010000; // Liga apenas o L5 (RD4)
        __delay_ms(200);
        PORTD = 0b00100000; // Liga apenas o L6 (RD5)
        __delay_ms(200);
        PORTD = 0b01000000; // Liga apenas o L7 (RD6)
        __delay_ms(200);
        PORTD = 0b10000000; // Liga apenas o L8 (RD7)
        __delay_ms(200);
    }
}
